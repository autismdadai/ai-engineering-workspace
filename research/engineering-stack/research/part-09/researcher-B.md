## (c) Facts a small standard-library lab should reproduce

1. Handoff vs agent-as-tool context movement (OAS B54-B56). Model a conversation as a list of messages. Handoff: the receiving agent's input = the full prior list (H messages) plus its own instructions; the receiver then owns the rest of the turn and its reply goes straight to the user. Agent-as-tool: the receiving agent's input = one generated string I chosen by the manager; it returns one string (final output); the manager keeps control and appends only that string to its own list. A lab can count characters or words entering each worker under both patterns and show that handoff cost grows with H while as_tool cost does not.
2. History filter. Reproduce an `input_filter` that drops tool items (like `remove_all_tools`) and show the leak the docs warn about: tool output already quoted in an ordinary assistant message survives the filter (B57).
3. What a Claude subagent sees and returns (CAS B76-B77). Worker input = its system prompt + the single prompt string from the parent (no parent history). Worker output to parent = final message only; intermediate tool results stay in the worker. A lab can simulate a worker that "reads" 20 files and show the parent's context grows only by the summary length.
4. Token arithmetic of an orchestrator with N workers (illustrative formula, not a measurement). Let P = orchestrator prompt, T = task brief per worker, R = tokens each worker reads, S = summary each worker returns. Workers process about N x (T + R + S). The orchestrator's context grows by about N x (T + S) instead of N x R. Total tokens processed rise, but the lead's context stays small. Example to compute in the lab: N = 3, R = 20,000, S = 1,000, T = 300 gives workers about 63,900 tokens and the lead's context about 3,900 extra tokens, versus about 60,000 if one agent read everything. Pair this with ANT's measured multipliers (about 4x chat for an agent, about 15x chat for multi-agent, B5-B6) and say clearly which numbers are measured and which are toy.
5. Error compounding (illustrative). If each of k sequential handoffs succeeds independently with probability p, end-to-end success is p^k (for example 0.95^5 is about 0.774). A lab can add a verifier step that catches a fraction c of errors to show why centralized verification contains errors better than independent workers (SCAL B36 reports 17.2x vs 4.4x trace-level amplification; do not claim the toy model reproduces those numbers).
6. Equal-budget comparison. Given a fixed budget of B "calls", compare one agent sampling B answers with majority vote (self-consistency) against a 3-agent, 2-round debate (6 generations, as in DU B45). A seeded random simulation can show that the comparison depends on how correlated the agents' errors are, which is the point of SMIT, ZHNG and TRAN.
7. Supervisor output modes (LGS B73). Simulate `last_message` vs `full_history`: count what the supervisor sees after each worker.
8. Prompt-injection spread (PINF B50-B52), safely: pass a harmless marker string (for example "MARKER-123") through a chain of toy agents that copy their input into their output, then add a tagging step that labels inter-agent text as data and show the marker is still present but now labelled. Do not reproduce the paper's infection prompt.
