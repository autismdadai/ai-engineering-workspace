## (b) Ledger rows settled

**P6-01, "ReAct is the foundational paradigm of agent engineering": overstated (stands).** ReAct (ICLR 2023) is an early, influential statement of the interleaved reason-act-observe loop (A51). It is not "the" foundation: on HotpotQA ReAct alone scored 27.4 EM against CoT-SC's 33.4, and its best result came from a hybrid with fallback (A56); in τ-bench's original airline tasks a native tool-calling agent beat ReAct-style prompting with gpt-4o, 0.420 vs 0.325 pass^1 (A57). Anthropic's agent definition (A41) and today's APIs (A01 to A16, A39) describe the loop with structured tool calls, not ReAct's text format. Suggested wording: "an influential early form of the tool loop".

**P6-03, the loop and step caps: confirmed, with two notes.** REA §3.2: "We set 7 and 5 steps for HotpotQA and FEVER respectively" (A52), with the ReAct → CoT-SC fallback when no answer arrives within the steps (A53). Note 1: ReAct's released notebooks use up to 7 steps for FEVER too, so code and paper differ for FEVER (A52). Note 2: "deterministic execution layer" is not in any source; vendor docs only say your code runs the tool and returns a result (A09, A39).

**P6-04, "error handling is the most critical component; stack traces let the model correct itself": overstated, and the stack-trace part is corrected.** ReAct's Table 2 puts reasoning errors first, at 47% of ReAct's sampled HotpotQA failures (50 failed trajectories, human-labelled, PaLM-540B); search-result errors were 23% (A55). Nothing ranks error handling as "most critical". On stack traces, vendor guidance goes the other way: Anthropic advises actionable messages "rather than opaque error codes or tracebacks" (A45, A11), and the OpenAI Agents SDK by default sends "An error occurred while running the tool. Please try again." without the exception (A34). Supported version: report tool failures to the model as results (is_error, error_as_result), with short, instructive text.

**P6-06, an agent issuing refunds on its own: illustrative; the ledger note is supported.** OWASP LLM06:2025 mitigation 6: "require a human to approve high-impact actions before they are taken" (A66), plus complete mediation in downstream systems (A67). LLM06 has no refund example; calling a refund "high-impact" is our reading [I]. The OpenAI Agents SDK provides needs_approval for this (A38), and the Claude Agent SDK provides the "default" permission mode with a canUseTool callback and PreToolUse hooks (A23, A24). Note: the ledger cites "OW5"; what I read is the 2025 list's LLM06 file. I did not check a 2026 OWASP edition.

**P6-07, a raw while-loop that runs local functions from model output: illustrative, matches the docs.** The documented client loop is: send tools, receive tool calls, run them, return results with the matching ID, repeat until a final answer (A19, A30, A39). A correct minimal loop must also handle the items in section (c); WTA itself recommends "simple agentic loops (while-loops wrapping alternating LLM API and tool calls)" for tool evaluation. The ledger's "needs input validation" stands: the model can call unknown tools or send malformed JSON (A33, A12), and strict tool use exists to prevent schema mismatches (A12).

**P7-01, "harness engineering" meaning test scaffolding, sandboxes and verification harnesses: corrected (stands), with refinements.** (1) OpenAI's February 11, 2026 post coined the usage in its title but never defines the term; its own description is designing "environments, feedback loops, and control systems" around Codex (A69, A70). (2) Böckeler, February 17, 2026: "tooling and practices we can use to keep AI agents in check" (A71). (3) "Guides and sensors" is defined in her April 2, 2026 article, which also gives "everything in an AI agent except the model itself" (A72, A73); the ledger dates it February 17, so correct the date or cite both. (4) Anthropic, November 26, 2025, calls the Agent SDK "a general-purpose agent harness" (A74), the built-in-harness sense. (5) The older evaluation sense (EleutherAI's harness, SWE-bench's and Terminal-Bench's harnesses) is real and still in use (A75). So the paper's definition merges three senses; the current one is the agent's working environment and its feedback and control around the model.

## (c) What a minimal correct loop must handle

1. Continue only on tool calls; stop on a final answer. Anthropic: continue when stop_reason is tool_use, stop on end_turn (A02, A03). OpenAI Agents SDK: final output is text of the desired type with no tool calls (A30). Agent SDK: loop ends at "a response with no tool calls" (A19).
2. Handle every other stop reason explicitly: max_tokens (retry with a higher limit if a tool_use block was cut off, never run a truncated call) (A05); pause_turn (send the response back to continue; server tools only) (A06); refusal (A07); stop_sequence; model_context_window_exceeded (A08). Sources: STOP.
3. Return one result per call, matched by ID, all in the next user message, results first and text after (A09, A10, A13; OpenAI: call_id, A39).
4. Report tool failures as results, not crashes: is_error true with an instructive message (A09, A11); OpenAI Agents SDK failure_error_function and error_as_result timeouts (A34, A35). Keep tracebacks out by default (A45).
5. Validate model-chosen calls before running them: unknown tool names, malformed JSON, missing parameters (A33, A12). Use strict schemas where offered (A12).
6. Cap the loop: a turn limit (BEA "maximum number of iterations", A42; OpenAI default 10, A31; Agent SDK max_turns, default none, A20), a spend cap (max_budget_usd, which can overshoot by one response, A21), and per-tool timeouts (A35). Decide what happens at the cap: raise (MaxTurnsExceeded, A32), return an error result (error_max_turns, A22), or fall back (ReAct → CoT-SC, A53).
7. Gate high-impact actions on a human or on code-level authorization (A66, A67, A38, A23). Logging and rate limits only limit damage (A68).
8. Decide parallel execution policy: the API doesn't fix an order; run side-effecting tools sequentially (A14, A26).
9. Watch context growth: history grows every turn (A28, A50); use tool-result clearing, compaction or subagents (A29, A46, A47), and cap tool output size (A45: 25,000 tokens in Claude Code).
10. Treat tool results as untrusted input: OWASP lists "direct/indirect prompt injection from ... an earlier invocation of a malicious/compromised extension" as a trigger for excessive agency (OW, Description). Details: Part 10.
