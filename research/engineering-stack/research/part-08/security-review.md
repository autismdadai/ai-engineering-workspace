## Tested and fine

- **Core lab network and files.** No lab file imports `socket`, `urllib`, `http` or `requests`, or uses `open()`/`os` writes. Only `mutation_check.py` starts processes: `subprocess.run([sys.executable, "run_lab.py"], cwd=folder, timeout=60)`, a list with no shell, and it writes only into its own temp copies. Running the lab leaves only `__pycache__` in its folder. `run_lab.py` gave 21 of 21, `mutation_check.py` gave 20 of 20 (about 17 s), and `demo.py` matched the part.
- **`not_a_sandbox.py` is harmless and clearly framed.** It only calls `os.getcwd()` and prints the path; it changes nothing. The docstring, the printout ("A real boundary is a separate process ..."), 3.9 and 7.7 frame it correctly, including the deprecation of `load_module`.
- **`crosscheck.py` makes no network calls.** Run under a guard that blocks and logs every `socket.connect` and `getaddrinfo`, with `HTTPS_PROXY`/`HTTP_PROXY` pointed at `127.0.0.1:9`: 3 of 3 passed with `NETGUARD attempts: []`, both without a key and with `OPENAI_API_KEY=sk-fake-not-real`. Control: the same guard on a copy with the two tracing lines removed and the fake key set logged 3 attempts and "Tracing request failed", so the guard does detect uploads. The model is the in-script `FakeModel`, so no OpenAI model client is used. The only network path found in the SDK's tracing code is the trace exporter (`https://api.openai.com/v1/traces/ingest`, `processors.py` line 46), and `crosscheck.py` turns it off before importing the SDK and again with `set_tracing_disabled(True)`.
- **Approval gate.** It isn't bypassed by tool-name casing (`Issue_Refund` gives `unknown tool`). The lab has no second path to the refund. The default approver is `deny_all`.
- **`max_tokens` retry.** A cut-off tool call is never run. The limit rises once (1024 to 4096), then the loop stops with `max_tokens` (test: `status max_tokens turns 2 budgets [1024, 4096]`). The token budget still applies (test 7b: `budget` after 1 call).
- **A tool raising `SystemExit`** in its thread is reported as an error result, not a crash.
- **Hardened command flags against Docker's docs (79e20f3):**
  - `--security-opt no-new-privileges` with no value is Docker's own example form (`docker run --security-opt no-new-privileges -it ubuntu bash`, yaml line 2499). `=true` is the table form; both work. `:true` isn't needed.
  - `--tmpfs /tmp:rw,noexec,nosuid,size=64m` follows the reference's own example (`--tmpfs /run:rw,noexec,nosuid,size=65536k`, line 1416). `noexec` doesn't stop Python reading or writing files in /tmp. It does block running binaries and loading compiled extensions from there, but not `python /tmp/x.py`, so it is a speed bump, not a boundary.
  - `--read-only` with user 65534: Python runs. It silently skips writing `.pyc` files, and anything that writes to `$HOME` or installs packages fails (`-e HOME=/tmp` helps). This is a usability point, not a safety one.
  - `--memory-swap` equal to `--memory` matches DRC.
  - AppArmor (`docker-default`) and the default seccomp profile stay on because nothing turns them off.
  - User namespaces are off by default, which 3.7 already states.
- **Section 3.8 to 3.11 advice.**
  - Sandbox claims are hedged with their sources ("not a substitute", "cannot guarantee", side channels).
  - The part never tells readers to run computer use on their own desktop; it lists Anthropic's four precautions.
  - Hosted sandboxes are flagged as sending code to someone else's machines.
  - 7.5 tells readers to read the install steps and ask the administrator first.
  - The Codex bypass flag is quoted with its warning.
- **Not counted as `sandbox_check.py` misses:** `--PRIVILEGED` and `--user ROOT`. Docker's flags and Linux user names are case-sensitive, so these aren't the dangerous options.
