## (c) Changes the picture

1. vLLM no longer swaps KV cache to CPU. Since V1 (the only engine in 0.31.0) a preempted request loses its blocks and is recomputed; "--swap-space" is gone and the V1 guide lists CPU swapping as removed (S050 to S053, S137). Text describing swap as a live option is outdated.
2. Benchmark metric names collide. AIPerf's "ITL" is (latency − TTFT)/(OSL − 1), which vLLM calls TPOT; vLLM's "ITL" is the gap between streamed chunks, which AIPerf calls ICL. With speculative decoding the two differ a lot (vLLM's example: 40 ms vs 20 ms per token). Define metrics by formula (S113 to S122).
3. Telemetry is on by default in several engines: vLLM sends to https://stats.vllm.ai unless VLLM_NO_USAGE_STATS=1, DO_NOT_TRACK=1 or a do_not_track file; TGI sends to Hugging Face when it runs in a container unless --usage-stats=off; TensorRT-LLM pre-releases (1.3.0rc29, 1.4.0rc0) send to NVIDIA unless TRTLLM_NO_USAGE_STATS=1 or similar, while stable 1.2.1 has no such module. No telemetry code was found in SGLang, LMDeploy or MLX-LM (S058 to S067).
4. TGI is in maintenance mode (README, since 2025-12-11), last tag v3.3.7 (2025-12-18), and Hugging Face itself points users to vLLM, SGLang, llama.cpp and MLX (S087, S088).
5. "pip install tensorrt_llm" from PyPI downloads a stub that pulls the real wheel from https://pypi.nvidia.com/. The newest stable release is 1.2.1 from April 2026; everything since is a release candidate. Wheels are Linux only (x86_64, aarch64), and hardware is NVIDIA only (S068 to S072, S140).
6. Speculative decoding gains depend on load and context length. At low load (batch size 1 or one query per second) measured gains run about 1.5x to 3.55x; with short contexts they shrink with concurrency and can turn into slowdowns; with long contexts they can survive large batches (S021, S022, S036, S135, S142, S143).
7. The vLLM paper's comparison numbers (20.4% to 38.2% used, 2x to 4x throughput) are against the authors' own reimplementations of Orca and against FasterTransformer, on A100s in 2023 (S012, S128). Scope them that way.
8. Defaults moved: vLLM 0.31.0 uses gpu_memory_utilization 0.92 (not 0.9) and max_num_seqs 256 or 1024 depending on GPU memory; prefix caching and chunked prefill are on by default in both vLLM and SGLang; SGLang computes its memory fraction per GPU instead of using a fixed number (S098 to S109).
9. Security notes for the paper: vLLM's --api-key does not protect /invocations, and the docs say not to rely on it alone; the MLX-LM server "is not recommended for production" (S081, S095).
10. A default "pip install vllm" pulls CUDA builds, 199 packages and about 3.93 GB of downloads (Linux x86_64, Python 3.13). CPU-only vLLM needs the +cpu wheel from GitHub releases (Linux x86 with AVX-512 recommended), and SGLang's CPU path targets 4th-generation or newer Intel Xeon with AMX (S078, S123 to S126).
