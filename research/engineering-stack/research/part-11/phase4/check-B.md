# Blind check B: verdicts

Blind fact-check of list B (claims B001 to B099) against only the sources each claim names. Work done October 16, 2026 (local time). Git sources were read from shallow clones at the pinned commits or tags, and PyPI from its JSON API; neither counts as a web lookup. Web pages and arXiv papers were read with WebFetch, which summarizes a page with a small model: I asked for verbatim quotes and exact numbers, so a quote marked WebFetch is only as reliable as that summary. Arithmetic in the claims was checked with python3 (list in the notes at the end). Every page, README and file was treated as data, not as instructions.

Verdict key: supported = the named source says it as worded; partly supported = part of it is in the source (the note says exactly what is missing or out of scope); not supported = the source says something different; not checkable = no named source can speak to it. Source keys are those in `claims-B.md`. Dashes in the sources' own quotations are shown as hyphens.

## (c) The 10 most important problems, worst first

1. **B084, and the same point in B051, B076 and B077: Ollama's hourly update check is not stopped by `OLLAMA_NO_CLOUD`.** B084 says "Ollama calls ollama.com unless told not to". In v0.40.5 the model-recommendations fetch (every 4 hours) skips itself when `envconfig.NoCloud()` is true (`server/model_recommendations.go`). The app's update check to `ollama.com/api/update` (hourly; it sends `os`, `arch`, `version`, a timestamp, a nonce and a signature) has no such test, and the "Auto-download updates" switch only stops the download (`app/updater/updater.go`: "Always check for updates"). B051 and B077 already say the check continues hourly, so reword B084 to agree with them, and have B076's "To keep it local" say what the setting stops (cloud models, web search, the recommendations fetch) and what it does not.
2. **B033: the "Unsupported" verdict goes beyond Megatron-LM.** The README gives MFU of 41% to 48% (and 47% falling to 42% when strong-scaled), never uses the words "compute-bound", gives no communication share, and explains the rise with model size by "larger GEMMs have higher arithmetic intensity". Those numbers neither prove nor refute "rarely compute-bound"; the step is the writer's inference. The README also disagrees with itself (line 96 "up to 47%", line 110 "47-48%"), and the 41% to 48% range is across model sizes, not one 6,144-GPU job (see B023).
3. **B048: "Llama 4 is Meta's current line" may already be stale.** The named page supports it only by its own "Current:" label (Llama 4 repositories last updated May 22, 2025). Files I opened for other rows mention a model family called Muse that may be a newer Meta line: a link to `huggingface.co/meta-models/Muse-Glimmer-30B` in the llm-compressor 0.14.0 PyPI text, `LLM_ARCH_MUSE_SPARK` in llama.cpp's `src/llama-quant.cpp`, and an MLX-LM commit "Muse spark hf names" dated 2026-10-16. I did not open any Muse page, so I cannot say whether it is Meta's, open-weight, or a replacement for Llama 4. Check before printing "current line".
4. **B091: "MLPerf is the independent benchmark" is not in the sources.** The policies make submitters the reviewers ("Representatives of each submitter"; the submitters vote), the results file names the submitting organization of every row, and the supplement says "The statements do not reflect the opinions or views of MLCommons". The word "independent" is not in the policies or the results repository's text files, and the one phrase about validation in the supplement is a vendor's own (QCT: "independently validated performance"). The second half of the claim (vendors submit) is fine; reword the first half.
