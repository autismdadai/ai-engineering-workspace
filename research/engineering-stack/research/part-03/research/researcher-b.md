## DSPy offline facts (in progress)
- DummyLM: dspy/utils/dummies.py, `class DummyLM(BaseLM)`, `__init__(self, answers: list[dict[str, Any]] | dict[str, dict[str, Any]], follow_examples: bool = False, reasoning: bool = False, adapter=None)`. Model name "dummy". Modes: list of dicts -> returns next dict in order; dict of dicts -> keyed by text contained in final message; follow_examples=True -> copies output of a matching demo. Output is formatted as adapter fields (ChatAdapter default), e.g. "[[## answer ##]]\nred". Uses DummyEngine (dspy/clients/engines/dummy_engine.py: "no provider SDK objects are needed"). Imports numpy lazily (`np = require("numpy")`); numpy is NOT a core dependency (optional extra), so DummyLM may need numpy installed when used.
- Dependencies (pyproject 3.4.0 at HEAD): requires-python ">=3.10, <3.16" (CONFLICT with known "<3.15"); litellm>=1.65.8 (only python<3.15); gepa[dspy]==0.1.4 (only python<3.15); optuna NOT core, extra `dspy[optuna]` (optuna>=3.4.0); openai>=1.66.2, requests, pydantic>=2.11.0, diskcache, json-repair, tenacity, etc.
- Telemetry: no telemetry/analytics code found in dspy/ (grep telemetry|posthog|analytics|sentry|mixpanel). dspy/clients/_litellm.py sets `litellm.telemetry = False` when LiteLLM is first loaded.
- Network on use: dspy/clients/model_metadata/__init__.py fetches LiteLLM's model_prices_and_context_window.json from raw.githubusercontent.com once on first use (5 s timeout, falls back to bundled snapshot); disabled by env LITELLM_LOCAL_MODEL_COST_MAP=true. Triggered by cost estimation/capabilities lookups, not by `import dspy` itself (lazy). For DummyLM, cost estimator returns "custom engine has no pricing provider" when provider is None (costs.py) - so likely no fetch, not run-verified.

Returns scripted answers formatted as adapter fields (ChatAdapter default, e.g. "[[## answer ##]]\nred"): list mode = next dict each call; dict mode = value whose key appears in the final message; follow_examples=True = copies output of a matching demo. Served by DummyEngine (dspy/clients/engines/dummy_engine.py: "no provider SDK objects are needed"). Response caching off for DummyLM. Module-level `np = require("numpy")`: numpy is an optional extra, so install numpy (or dspy[numpy]) to use DummyLM. Used throughout tests/teleprompt/ (e.g. test_bootstrap.py).
- Dependencies (released 3.4.0, PyPI JSON): python >=3.10,<3.15; litellm>=1.65.8 (core); gepa[dspy]==0.1.4 (core, exact pin); optuna>=3.4.0 only via `dspy[optuna]` (MIPROv2 raises an ImportError with that hint if missing); numpy only via extra. gepa 0.1.4 itself: MIT, python >=3.10,<3.15, no core deps.
- Telemetry: no telemetry/analytics code in dspy/ (grep for telemetry, posthog, analytics, sentry, mixpanel; wheel and HEAD). dspy/clients/_litellm.py sets `litellm.telemetry = False`, `litellm.cache = None`, `suppress_debug_info = True` when LiteLLM is first loaded. dspy loads LiteLLM lazily via require(); top-level `from litellm import` lines are TYPE_CHECKING-only. So `import dspy` should not import LiteLLM (static reading, not run).
- Network on use: (1) dspy/clients/model_metadata/__init__.py fetches https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json once on first pricing/capability lookup (5 s timeout, falls back to bundled snapshot); off with env LITELLM_LOCAL_MODEL_COST_MAP=true. (2) LiteLLM itself (checked v1.105.0 wheel) fetches the same cost map at import (`model_cost = get_model_cost_map(url=model_cost_map_url)`) unless LITELLM_LOCAL_MODEL_COST_MAP=true. For DummyLM, cost estimate returns "custom engine has no pricing provider" when provider is None, so likely no fetch; not run-verified. (3) gepa/__init__.py imports gepa.examples.aime, which calls datasets.load_dataset only inside a function (not at import).
- Recommended offline env for tests: LITELLM_LOCAL_MODEL_COST_MAP=true; DSPY cache dir is created on first `dspy.cache` access (lazy).

## Conflicts and surprises
- Python range: released 3.4.0 says <3.15 (matches ALREADY KNOWN); repo HEAD says <3.16 and makes litellm/gepa conditional. Repo HEAD still labels itself 3.4.0. Cite PyPI for 3.4.0.
- 3.4.0 ships a vendored "lm15" engine (dspy/_vendor/lm15) that is the default native LM path; LiteLLM is the compatibility engine. The docs page still describes providers as "supported by LiteLLM".
- ICLR 2024 page titles the DSPy paper "...into State-of-the-Art Pipelines"; arXiv title is "...into Self-Improving Pipelines".
- GEPA abstract v2 says "up to 35x fewer rollouts"; body Obs. 1 says "4-35x fewer rollouts" (PDF) and "up to 78x greater sample efficiency" (vs GRPO's best validation). HTML extraction once rendered "44–35×"; a second PDF read confirmed "4–35×". Obs. 1 also says GEPA beats GRPO "by up to 19% while using up to 35× fewer rollouts".
- MIPROv2 fell below the unoptimized baseline on Qwen3 8B for AIME-2025 (20.00 vs 27.33) and LiveBench-Math (46.60 vs 48.70) in the GEPA paper's Table 1.
- In the MIPRO paper Table 2, Bootstrap RS (demos only) beat MIPRO on Iris and Heart Disease test.
- GEPA AIME tutorial calls 46.7% -> 56.7% "a 10% improvement"; it is +10 percentage points (about 21% relative).
- GEPA-Qwen-Opt row (Table 2): prompts optimized on Qwen3-8B kept most of the gain on GPT-4.1 Mini (+9.00 vs +12.19 when optimized in place). The Lemos et al. study found the opposite for one case (optimized prompt did not help a cheaper model).
