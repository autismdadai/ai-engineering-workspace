## Ledger rows

- **P1-08 (Anthropic Workbench)**: CONFIRMED with detail. Support article "How do I use the Workbench?" (updated July 16, 2026) says "Log in to the Claude Console", so a Console account is needed (A48). The billing article says "Claude API and Workbench usage is billed via prepaid usage credits", so it spends API credits (A49). Workbench is "built directly on the public Messages API".
- **P1-09 ("zero-shot role prompting enforces output determinism for JSON ticket routing")**: UNSUPPORTED (we keep our position). No source read says a role prompt enforces format or determinism. Format guarantees come from API mechanisms: strict tools or output_config.format (Anthropic, A05-A07), strict Structured Outputs (OpenAI, A16-A21), grammars (A31-A38). Ollama's own docs say to lower temperature "for more deterministic completions" (A35), which is separate from format. Anthropic 5.x models reject non-default temperature (A55). No source promises identical reruns.
- **P1-11 ("a system prompt can severely penalize out-of-character tokens")**: CORRECTED. Token-level hard control is logit_bias: -100..100 added to logits before sampling, ±100 means ban or exclusive selection (A24). It exists only on Chat Completions and legacy Completions, not on the Responses API (A25), and nothing like it was found in Anthropic's docs. The other hard control is constrained decoding (A31-A38). The reasoning guide says nothing about logit_bias on reasoning models (not found). Our wording stands: a prompt shifts probabilities softly.
- **P1-13 (role separation)**: CONFIRMED with nuance. OpenAI has user/assistant/system/developer roles. Developer is "prioritized ahead of user messages", per the Model Spec chain of command, which is behavior trained into the model (A66-A67). Anthropic uses a `system` parameter plus user/assistant messages. The page read states no priority rule (A68). Neither source describes the priority as enforced by code.
- **P1-15 ("schema enforcement bridges text and deterministic software execution")**: CORRECTED to our wording. Strict mode guarantees schema shape only: "guarantees that tool inputs will always match your schema exactly" (A12). There are exceptions: refusals may not follow the schema (A23), and per the already-read Anthropic page, refusal and max_tokens cases too. Local engines support only a subset and silently skip unsupported keywords (A34). JSONSchemaBench shows coverage gaps across engines (A45). No source claims correct values or identical reruns.
- **P6-02 ("in ReAct tools are strictly mapped via JSON schemas")**: CORRECTED. ReAct (ICLR 2023) §3.1 uses plain-text actions search[entity], lookup[string] and finish[answer]. The official prompts use "Action 1: Search[...]". The paper text read has no JSON schema (A47).

## Conflicts and surprises

1. Anthropic: forced tool_choice (`any`/`tool`) is NOT supported on Claude Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1, nor with manual extended thinking. On models that accept it, forcing a tool skips thinking (A05, A06). For guaranteed schema-valid tool calls on these models, the docs recommend `auto` plus `strict`, or structured outputs. Any claim that "tool_choice any + strict guarantees a call" needs this model caveat.
2. Anthropic manual extended thinking (`budget_tokens`) is deprecated on 4.6 and rejected (400) on 4.7+. Use adaptive thinking plus `output_config.effort` (A51). Effort defaults to medium on Opus 5.5 and Haiku 5.5, high elsewhere (A57).
3. Anthropic 5.x-era models return 400 for any non-default temperature/top_p/top_k, even without thinking (A55). This matters for any "set temperature 0 for determinism" advice aimed at Claude.
4. On newer Claude models, thinking is returned "omitted" by default, and no setting returns the raw chain of thought (A53).
5. OpenAI reasoning effort now includes `max` (A61), which the brief did not list.
6. OpenAI Responses API "will attempt to normalize your schema into strict mode when possible". That is softer than "strict on by default" (A16). In the OpenAPI spec, `strict` is a required (nullable) field on FunctionTool (A15).
7. The current OpenAI Structured Outputs guide text I could read lists supported types and keywords, but did NOT show the nesting-depth, property-count or string-length limits, or the root-not-anyOf rule. I read four offsets; the summarizer may have dropped them (A22). Do not cite numeric limits without opening the page in a browser.
8. The OpenAI cookbook "Structured Outputs Intro" text still describes the 2024 Chat Completions/Assistants launch (A71). Cite it as a launch-era example.
9. Tam et al. venue confirmed: EMNLP 2024 Industry Track. The dottxt rebuttal comes from a vendor that sells structured generation. Its re-run is one model (Llama-3-8B-Instruct) (A42, A43).
10. JSONSchemaBench (2025) found constrained decoding improved quality slightly over unconstrained (GSM8K 80.1% to 83.8% with Guidance, Llama-3.1-8B-Instruct) (A46). That points the opposite way from Tam et al.'s reasoning finding. The setups differ: different prompts, engines and models.
11. llama.cpp's response_format schema is not shown to the model. Ollama likewise advises putting the schema in the prompt too (A33, A35). A constraint is not an instruction.
