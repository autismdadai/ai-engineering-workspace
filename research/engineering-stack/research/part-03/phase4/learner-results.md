## Problems

1. LOW-MEDIUM. Section 7.6 row 2 quotes: `Hashes are required in --require-hashes mode, but they are missing from the following requirement`.
   Actual (pip 26.2.1 and pip 24.0): `ERROR: Hashes are required in --require-hashes mode, but they are missing from some requirements. Here is a list of those requirements along with the hashes their downloaded archives actually had. ... dspy==3.4.0 --hash=sha256:36de...`.
   Why it matters: a beginner searching the table for the text they see will not find it by exact match; the pip message also suggests "add hashes", which is the wrong fix here. Fix: quote `Hashes are required in --require-hashes mode, but they are missing from some requirements` and add "(pip then lists dspy==3.4.0; ignore its advice to add hashes)".
2. MEDIUM. Section 7.3 / 7.2: "The same commands as macOS" starts with `cd ~/ai-stack/engineering-stack-lab-part-03`. No step says to create `~/ai-stack` or how to unzip (Linux: `unzip file.zip -d ~/ai-stack`; the "Before you start" line only says "Unzip ... into your series folder"). `unzip` was installed here but is not guaranteed on a minimal Ubuntu. Also `python3 -m venv` on stock Ubuntu may need `sudo apt install python3-venv` (worked here; not tested on a stock desktop image, so unverified). Fix: give an explicit unzip command and one line about python3-venv.
3. MEDIUM (untested, from reasoning plus simulation). Section 8 step 1: `python ticket_contract.py > ticket_schema.json`. In Windows PowerShell 5.1 `>` writes UTF-16. I simulated that file (iconv to UTF-16) and the linter fails: `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0: invalid start byte`. Fix: for Windows tell readers to use PowerShell 7 or `python ticket_contract.py | Out-File -Encoding utf8 ticket_schema.json`, or make schema_lint.py open with `utf-8-sig`/try UTF-16. Section 7.1 is marked [R: no Windows test machine], so this is unconfirmed on Windows.
4. MEDIUM. Section 8 steps 1 and 2 say "exit code 0" / "exit code 1" but never say how to see an exit code. Fix: add `echo $?` (macOS/Linux) and `echo $LASTEXITCODE` (PowerShell) after the commands.

7. LOW-MEDIUM. Exercise 1 is written with `"queue": ...` as a placeholder, and doesn't say where to save the schema or that it needs `"type": "object"`. I tried the schema without `"type": "object"` (properties, required, additionalProperties false only): the linter prints `{"anthropic": [], "openai": [], "ok": true}` with exit 0, a false all-clear, because the linter only checks nodes whose type is "object". Fix: give the full JSON for the exercise; add a line "the linter only checks objects whose type is object" or make the lint flag a schema with properties but no type.
