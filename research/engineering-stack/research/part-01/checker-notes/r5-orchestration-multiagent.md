# R5: Orchestration and multi-agent framework claims (audit of "The Modern AI Engineering Stack")

Audit date: 2026-10-09. Paper class: AI-written (Gemini Deep Research), lowest trust; used only as a list of claims. I had the claim paraphrases, not the paper's own sentences, so "matches the paper" judgements rest on those paraphrases.

Method limits (read first):
- Web lookups used: 39 of 40 at the time of this save (see section 7). Every page was read through the WebFetch tool, which returns a model-written digest of the page, not raw text. "The page says X" is reliable enough to cite; "the page does not mention X" is weaker, because a digest can miss things. Section headings below are as the digest reported them.
- Quotes are kept to short phrases. Numbers carry their scope (model, eval, version, date).
- Pages containing text aimed at AI systems: W33 (TrueFoundry) has "Summarize with" buttons for chat assistants with prefilled prompts and a footer link "Hey AI, learn about us" (to /llm-info). Temporal's docs page links an llms.txt file. No page contained instructions to override behaviour; none of it was followed.
- Domain moves seen: platform.openai.com/docs/... redirects (302) to developers.openai.com/api/docs/...; cognition.ai/blog/... redirects (302) to cognition.com/blog/.... Citations below use the final URLs.

## 5. Answers to the 8 questions

**Q1. OpenAI Assistants API: dates, replacement, usable today?**
- OpenAI's deprecations page lists it under "Past deprecations" in an entry headed "2025-08-20: Assistants API". The text says developers were notified on August 26, 2025, and gives August 26, 2026 as the shutdown date. The replacement is the Responses API and Conversations API, with a migration guide. **Q5. Counter-evidence on multi-agent systems (B1-01)**

- Cognition, "Don't Build Multi-Agents" (Walden Yan, 2025-06-12, vendor opinion; Cognition sells Devin): two principles, share context (full traces) and actions carry implicit decisions; subagents with partial context make conflicting choices (Flappy Bird example); recommends a single-threaded linear agent, with a context-compression model for long tasks; author says the theory may change. No benchmark in the digest. https://cognition.com/blog/dont-build-multi-agents
- Cemri et al., "Why Do Multi-Agent LLM Systems Fail?" (arXiv 2503.13657, preprint; v3 2025-10-26; 13 authors): MAST taxonomy of 14 failure modes in 3 categories (system design issues, inter-agent misalignment, task verification), built from 150 traces (annotator kappa 0.88), then MAST-Data with 1,600+ annotated traces from 7 frameworks; an LLM-as-a-Judge annotator; models seen include GPT-4, Claude 3, Qwen2.5, CodeLlama; tasks: coding, math, general agents. - Net: none supports "specialized agents fix a fragile mega-prompt" as a general rule; the evidence is task-dependent, costly in tokens, and shows frequent failure modes.

**Q6. Anthropic "Building effective agents" (2024-12-19)**
- Workflows = LLMs and tools orchestrated through predefined code paths; agents = LLMs that direct their own process. Patterns: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer, autonomous agents.
- Routing: a classifier sends an input to a specialized follow-up; example: easy or common questions to smaller cost-efficient models, hard or unusual ones to more capable models (current text names Haiku 4.5 and Sonnet 4.5).
- Evaluator-optimizer: one call generates, another evaluates with feedback, in a loop; clear criteria matter; no score threshold mentioned.
- Start simple: find the simplest solution and add complexity only when it demonstrably helps; agentic systems trade latency and cost for performance; often one optimized call with retrieval and examples suffices. Frameworks can obscure prompts and responses; start with the LLM API directly. As digested, the framework list is Claude Agent SDK, Strands Agents SDK, Rivet, Vellum (no LangGraph). https://www.anthropic.com/engineering/building-effective-agents

**Q7. Exponential backoff with jitter**
- AWS Architecture Blog (Marc Brooker, 2015-03-04; May 2023 update note says most AWS SDKs include backoff and jitter): simulation of many clients contending on one record; Full Jitter did the least total work, Decorrelated Jitter finished fastest, plain exponential backoff without jitter did worst; conclusion: jittered backoff should be standard for remote clients. Scope: optimistic-concurrency simulation, not LLM APIs. https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/
- OpenAI rate-limit guide: on 429 follow Retry-After as a minimum; otherwise back off with growing delays; cap attempts and total retry time; add random jitter; disable SDK retries or count them to avoid nested retry loops; its Tenacity and backoff examples do not read Retry-After; use the Batch API for non-urgent work. https://developers.openai.com/api/docs/guides/rate-limits
