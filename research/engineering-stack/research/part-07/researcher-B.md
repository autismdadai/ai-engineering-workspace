## (c) Claims commonly repeated online that the sources don't support

1. "Agent Cards live at /.well-known/agent.json." This was true only through v0.2.x. Since v0.3.0, and in v1.0, the path is /.well-known/agent-card.json (B04, B05).
2. "A2A uses only JSON-RPC over HTTP." v1.0 defines three equal bindings: JSON-RPC, gRPC and HTTP+JSON (B12).
3. "A2A is a Google protocol." Google created it, but since 2025-06-23 it has been a Linux Foundation project with an eight-company TSC, and since August 2026 an AAIF project (B18-B20).
4. "A2A and MCP compete." Both specs and the A2A site call them complementary: MCP inside an agent, A2A between agents (B03).
5. "ACP is a live alternative to A2A." IBM's ACP merged into A2A in August 2025. Another unrelated "ACP" (Zed's Agent Client Protocol, editor to coding agent) exists. This is background knowledge, not checked here, so always spell out the full name (B22).
6. "AG-UI has 16 event types." The README still says "~16", but the 1.0 enum has 31 (B28).
7. "Agent Skills / AG-UI / AP2 were donated to the Agentic AI Foundation." None appears on aaif.io/projects as of 2026-10-14 (B33). The AAIF founding projects were MCP, goose and AGENTS.md. A2A, agentgateway and Agent Router joined later.
8. "Skill descriptions are limited to 200 characters." The open spec and the Claude API allow 1,024. The 200-character limit is in the Claude app help center for uploaded skills only (B37, B41, B43).
9. "The open spec bans 'claude'/'anthropic' in skill names." That rule is Anthropic's product rule, not part of agentskills.io (B41 vs B36).
10. "CVE-2025-49596 is CVSS 9.4 (v3.1)." 9.4 is a CVSS 4.0 score from GitHub as CNA. NVD has no 3.1 score (B58). Likewise, CVE-2025-6514's 9.6 comes from the CNA (JFrog), not NIST (B57).
11. "Models fail when given more than 20 tools." The "20" is OpenAI's advice, not a measured cliff (B61). The measured evidence (B62-B65) shows retrieval or search over tools helps, with gains that depend on the benchmark and model.
12. "Rug pull" and "tool poisoning" are often presented as standard terms from the MCP spec. They come from a vendor disclosure (Invariant Labs, 2025-04-01), not from the spec (B50).
